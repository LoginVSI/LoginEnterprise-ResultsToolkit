# Focused bug hunt, 4 November 2026

One finite self-review of the recent native-score, live-connector, report and job changes by the author's session. It is not an independent audit. It inspected metric identity and units, native states, bounds and change rules, failure denominators, missing timings, HTML/PDF/Power BI agreement, job last-good preservation and generated model compatibility against existing fixtures.

| Severity | Finding | Reproduction | Disposition |
|---|---|---|---|
| Medium (runtime) | A native-only live project still generated the timer `Results` query, which fetches every session and execution and refuses more than ten sessions. A real Load result often exceeds ten sessions, so a project that only wants whole-run scores would fail to refresh for an unrelated reason | Read `Fetch` in `adapters/powerbi/ResultsToolkit.pq` (`More than ten sessions`) and `report-live` output for `examples/live-native-report.json`, which contained `Acquisition.pq` and a `Results` table | Fixed. Native-only projects now contain only `NativeAcquisition.pq` and the `NativeScores` table, with one native visual. Mixed projects keep the timer table and its ten-session bound. Regression: `test_native_only_live_project_has_no_timer_query_and_leaves_timing_projects_alone` |
| Low (display) | The HTML change line blamed a not-completed state when the real cause was a zero baseline | Native comparison with baseline score 0 and candidate 5 | Fixed with a specific message. Regression: `test_native_zero_baseline_is_not_blamed_on_state` |
| Checked, no defect | Native change needs both states `completed`; VSImax above threshold shows as a lower bound and is never subtracted; null and zero stay distinct; one run per side is enforced in Python and in the connector; failure counts come from execution states, not timings | Existing tests plus the two above | None needed |
| Checked, no defect | Job failure keeps the last good run, and status reports last attempt, last success and source freshness separately | `tests/test_job.py` | None needed |

Not covered: Power Query runtime behavior and Desktop rendering of the native snapshot and live candidate, which still need the Desktop acceptance.

## Defects found by the Desktop acceptance (4 November, same day)

Running the native candidates in Power BI Desktop found two defects that the static checks and tests could not.

| Severity | Finding | Reproduction | Disposition |
|---|---|---|---|
| Medium (misleading error) | A rejected or expired Key token made the shared `Get` fail with "cannot convert the value null to type Logical". A rejected token returns a `Response.Status` field whose value is null, and `Get` compared it to numbers. This affected every live project, not only native scores | Observed in Desktop with a stale token; reproduced with a deliberately invalid fake token against the version endpoint (the status field is present and null) | Fixed. `Get` now raises an authentication error that names the likely cause and the Data source settings. Source guard test added. The credential-rejected path is source-guarded and was reproduced for the null status; the new message itself has not been seen in Desktop |
| Medium (rendering) | The native table showed only 3 of 8 rows after a successful refresh. Power BI hides table rows whose measures are all blank, which hid the EUX-disabled run and the VSImax above-threshold rows, the rows that carry the caveats | Desktop screenshot of the refreshed live project | Fixed. The native project now has a columns-only table that lists every row with display value, state and availability, and a second table with the comparable-score measures. Mixed projects put them on a second page. Regression test added; verified in Desktop by screenshot |

Both were found only by running Desktop; parser and schema checks passed on the defective builds.
