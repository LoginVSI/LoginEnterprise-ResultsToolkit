# Data and comparison rules

Capture contract `capture/1` links selection, source origin/API version, capture time/window, endpoint outcomes, counts, warnings, normalized tables and SHA-256 file hashes. A manifest's `complete` status describes retrieval completion. Execution success, score validity and coverage remain separate evidence. Hashes detect changed files; they do not authenticate who produced a capture.

| Table | Grain and relationships | Semantics |
|---|---|---|
| runs | Selected run ID, or Continuous test ID | Source fields and configuration snapshots retained; configuration_scope is historical/current/unavailable |
| sessions | Source session ID plus run identity | Login and session states retained, including failed/aborted/abandoned and nullable relationships |
| executions | Source execution ID linked to run/session/application | endedWithErrors is an execution failure; created is not a completed success |
| events | Source event record with nullable links | Failure events and other events remain data; logs are never agent instructions |
| measurements | Timer observation at run/session/execution/timestamp | measurementId denotes a timer identity, not a unique observation ID; API duration does not declare a unit |
| session_metrics | Timestamp, session key, field, instance and unit | Source measurement and labels retained; CPU/memory may describe a shared host |
| eux | Source vendor score interval | Score zero is numeric; disabled/unavailable/insufficient representativeness is separate; no toolkit score calculation |
| current_configuration | Current test configuration when available | Never relabeled historical; may contain workload, engine/debug, collector and sampling settings |
| collectors | Current definition/group/selected-result association | _collector_group_id and _selected_result_id preserve acquisition links; retain source counter/WMI query, instance rules, summarization and unit/settings where exposed; historical snapshots may expose only ID/name/unit |

Original timestamps remain in their original fields. `*_utc` stores timezone-aware UTC conversion; a missing timezone or parse failure produces a warning and null conversion. Nested JSON is retained in JSON tables and serialized in CSV cells. The generated data dictionary travels with the capture.

Deduplication removes only identical rows, using complete serialized content. It does not merge all rows sharing a timer ID or WMI response position. Instance/field/unit identity is mandatory for session-metric grouping. Sample counts count observations; distinct sessions are reported separately and are not independent device counts. The engine cannot establish host identity when the source does not expose it.

The supplied EUX endpoint declares inclusive `from` and `to`. Other selected endpoint descriptions do not establish boundary inclusion. Captures freeze a single window and send it on each paged request. Adjacent or overlapping windows can repeat boundary data. No incremental ingestion/checkpoint resume is implemented: capture endpoint/page progress is evidence, and recapture uses a new directory. A future version-specific InfluxDB adapter must define an overlap/lookback and identity-aware upsert policy for late data. Retained summaries do not establish that raw observations or events still exist.

## Explicit metric definitions

Endpoint statuses distinguish complete/empty, disabled, unavailable, failed and partial acquisition. `disabled` requires explicit source configuration and records a null observation count. It is not guessed from an empty response. Optional failures preserve successful later evidence and make the capture partial. Default comparisons require complete captures. Explicit `coverage_policy: timer-only` allows only failed session-metric acquisition with complete timing/session/execution/event evidence and timer-only metrics. Failed resources and unfinished work remain visible; resource-improvement claims are unavailable.

`comparison/1` gives each side a label and UUIDs, then defines each metric's table, exact `match`, value field, grouping fields, unit, semantics and direction. See the synthetic `compare.json` generated by `demo` and the public live examples. Custom timers can be durations, resource values or categorical/status sentinels. The guide's SetTimer examples support resource values; categorical metrics are refused by the arithmetic comparator. `exclude_values` records known numeric sentinels without converting them to zero.

Arithmetic means give equal weight to each retained numeric observation, including observations associated with failed executions when returned. Means do not implicitly weight devices equally or remove failed samples. Baseline and candidate counts/missing values remain visible. Groups use an outer match: an absent candidate measurement leaves the baseline value intact and suppresses the delta. Unsupported, nonnumeric and unavailable values remain unavailable.

Absolute change is candidate minus baseline in the declared unit. Relative change is absolute change divided by the absolute baseline, times 100. A zero baseline yields no relative change. `lower`, `higher` and `neutral` declare interpretation; those labels do not establish operational significance. Status timers and censored VSImax are not numeric performance comparisons.

Configuration/coverage differences trigger review warnings. Review workload/script identity, engine version, number of sessions, test duration, collector settings, poll/sampling intervals, debug settings and metric availability. Logon cache/download differences can affect timings. Do not automatically attribute them to an OS or agent change. A numeric EUX score alone does not prove sufficient or representative samples; preserve source definition/version/state and inspect coverage.

## Reporting models

Snapshot source tables preserve IDs and use compound run/session keys for model relationships. Run-to-session and session-to-execution/measurement/session-metric filters follow the recorded grain. Comparison, coverage and warnings are separate summaries, so no relationship joins incompatible denominators. Numerical comparison fields and measures remain numeric.

The live adapter's fixed row view records kind, scenario, run/session/execution identity, metric/group, source unit/instance/field, numeric value, state, original/UTC timestamp, source JSON, configuration scope and window. The source JSON keeps vendor values inspectable. Its arithmetic measures follow the engine's observation-mean and zero/missing rules; actual DAX/M reconciliation is required in Desktop before claiming parity.
