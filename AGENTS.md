# Project rules

This is a public, unsupported community preview. Josh is the product and technical owner. The customer outcome is less repetitive work between a Login Enterprise result and a trustworthy comparison or report.

- Read `docs/progress.md` before resuming. Update evidence and next work after substantial changes.
- Keep the deterministic Python engine authoritative. PowerShell and AI workflows are thin adapters.
- Use only the explicit v8-preview contract. No silent version fallback. Appliance access is read-only and bounded.
- Keep credentials in verified native vaults, never reports, parameters, logs, prompts or files. Reject unsafe persistence backends.
- Preserve raw evidence, IDs, units, timestamps, grain, failures, unavailable values and completeness. Never substitute zero for missing data.
- Use explicit baseline/candidate metadata. Names do not establish operating system or causality.
- Preserve user changes. Stage scoped files. No force pushes, releases or automatic main merges.
- Keep private references, captures and personal configuration under ignored `.private/` or external application configuration. No private files may be tracked.
- Separate implemented, offline-verified, appliance-verified and Desktop-verified claims. An agent's own review is not an independent Claude audit.
- Public prose should sound natural. No em dashes, repetitive cadence, filler or invented benchmark results.
- Preserve licensing decisions for the owner. Public source without reuse terms must not be copied.

Run `.venv/Scripts/python.exe -m pytest`, `ruff check .`, and `mypy src` on Windows, or the equivalent environment executables elsewhere. See `docs/quickstart.md` for installation.
